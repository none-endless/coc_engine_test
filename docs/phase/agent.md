### 重点要求

1. 不要硬编码,将外部注入类型的数据建立在外部
2. llm的输入输出一定要精确且简短
3. agent的修改需要同时修改提示词,代码,输出Json,配置信息集成在外部
4. 对于所有测试需要使用真实LLM完成
5. 规范(draft_spec)优先
6. 完成任务后产出汇报文档到donlist中
7. 每个函数和对象必须提供中文注释
8. 所有实现必须要保障响应智能,玩家自由度高,实现线下跑团级的高代入自由体验同时保障可落地,

### 其它问题
1. 环境统一策略
- 真实联调统一使用一个解释器（优先conda），固定命令前缀执行。
- 启动脚本前显式设置PYTHONPATH=.
- 将依赖安装命令和运行命令写入donelist，避免口头约定。

2. 可观测性与证据沉淀
- 三条真实用例必须输出终端过程，并同时落盘log与json。


3. 配置到请求体闭环
- 配置新增llm.enable_reasoning后，请求体同步传递关闭推理参数，确保配置项真实生效。
- 对不支持结构化输出的提供方保留降级路径，保证链路可用性。

4. 变更同步机制
- 每次agent相关改动，按提示词->模型->代码->配置->测试报告的顺序检查一遍。
- 发现字段契约变化时，先改数据模型再改提示词和调用方，最后回归测试。

5. LLM测试流程约束
- 需要真实LLM调用的测试，先向你确认密钥与执行窗口，再执行。
- 测试完成后立即写入phase对应donelist，记录输入、过程、结果、失败原因与修复动作。
