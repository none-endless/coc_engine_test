
## 最终plan
- 以规范为基线，抽取各 agent 的必要上下文要求，来源是 docs/spec/draft_spec.md 和 docs/spec/开发人员手册.md。
对照输入契约，确认每个 agent 理论可接收字段，来源是 src/data/model/agent_input.py 和 src/data/model/input/agent_map_intput.py。
对照运行时组装代码，确认真正喂给 LLM 的字段，来源是 src/engine/turn_orchestrator.py 与 src/engine/engine.py。
用真实日志二次验证，来源是 world/log/agent_io.jsonl。
总览结论

DM、Narrative、Merger 的上下文总体够用，缺口不大。
Evolution 有一个中等缺口：只拿到规则“结果类型”，拿不到更细的对抗结构。
重点三块里：
state_change_agent：主功能上下文基本充足，但“可移动目标集”在当前场景被压缩。
npc_scheduler_agent：存在两个高优先级缺口，会直接导致“看起来要调度、最终却空调度”。
npc_performer_agent：存在两个中优先级缺口，会降低目标变更与行为贴合度。
重点三模块差异

 state_change_agent

已有上下文：e4 summary、可写字段清单、失败反馈重试注入。
证据在 src/engine/turn_orchestrator.py、src/engine/engine.py。
缺失上下文（P1）：“可移动目标地图集合”在当前场景几乎只剩当前地图，导致 MOVE 决策空间不足。
证据在 src/utils/world_provider.py 和 src/utils/world_provider.py。
日志中可见“可选目标地图ID只有 map-longzhong_path-0001”，见 world/log/agent_io.jsonl。
影响：状态代理不是不会写，而是“可写范围被场景连接信息缩窄”。
npc_scheduler_agent

缺失上下文（P0）：没有稳定的“合法候选 NPC ID 列表”输入，只能靠 LLM自由生成。
系统后处理会做存在性过滤，见 src/agent/llm/npc_schedul_agent.py 和 src/agent/llm/npc_schedul_agent.py。
这会出现“raw_output有 ID、最终 scheduled_npc_ids 变空”的现象，见 world/log/agent_io.jsonl 与 world/log/agent_io.jsonl。
缺失上下文（P1）：模型契约里有 narrative_info，但发送前被主动去掉。
契约定义在 src/data/model/agent_input.py 和 src/data/model/agent_input.py。
实际发送前被 pop 在 src/agent/llm/npc_schedul_agent.py。
缺失上下文（P1）：adjacent_maps 在当前世界里长期为空，调度视野过窄。
日志证据 world/log/agent_io.jsonl。
根因链路是连接解析依赖 target_map_id 或 connection.id 命中地图 ID，见 src/data/model/world_state.py 与 src/data/model/world_state.py。
当前地图连接定义使用 conn-longzhong-to-courtyard-0001，见 world/三顾茅庐/map/maps.json。
npc_performer_agent

缺失上下文（P1）：输入里没有当前 Goal（base_goal/active_goal），只有 memory。
输入模型见 src/data/model/agent_input.py 与 src/data/model/agent_input.py。
Goal 模型独立存在于 src/data/model/base.py，但未传入 performer llm_input。
影响：模型要判断“是否变更目标”时缺少当前目标基线。
缺失上下文（P1）：e1 传的是 scheduler summary，不是玩家原始输入。
证据在 src/engine/engine.py。
影响：NPC 对玩家原始动作语义的细节感知会被二次摘要损耗。
缺失上下文（P2）：NPC world view 仅含基础信息与描述，不含关系结构化字段。
证据在 src/data/model/input/agent_map_intput.py 与 src/utils/world_provider.py。
影响：Prompt要求“符合关系与礼序”，但关系主要靠文本推断。
其他模型简结（按“必要功能”看）

dmagent：上下文齐全，必要功能可完成。
evolution：有 P2 缺口。E3 仅有 success，见 src/data/model/agent_input.py 和 src/data/model/agent_input.py，对复杂对抗叙事的可解释性偏弱。
narrative 与 merger：当前上下文可满足必要功能。
