- 世界文件制作
- 配置与模型接入
- 运行与调试
- 常见扩展点

## 3. 创建一个新世界
### 3.1 新建场景文件
在 `world/` 下新增 JSON，例如 `world/my_scene.json`，字段最小集合：
- `scene_name`
- `default_actor_id`
- `default_mode`
- `turn_start`
- `recommended_inputs` / `scripted_inputs`
- `store`：包含 `maps` / `characters` / `items`

可复制 `world/simple_stage_scene.json` 后修改。

### 3.2 实体 ID 规范
遵循草案规范：
- 地图：`map-xxx-0000`
- 角色：`char-xxx-0000`
- 物品：`item-xxx-0000`
- 玩家固定 ID 建议：`char-player-0000`

### 3.3 必填属性约束
角色属性必须包含“敏捷/dexterity”这一核心字段，否则引擎启动会被拦截（`validate_required_dexterity`）。

### 3.4 地图连接与重要角色
- 地图连接必须优先填写 `target_map_id`，值为目标地图实体 ID，例如 `map-corridor-0002`。`connection.id` 只表示连接自身 ID，不应兼作地图 ID。
- `state_change_agent` 的相邻地图上下文由当前地图的 `connections[*].target_map_id` 派生，并会向 LLM 提供相邻地图 `map_id`、`map_name`、`direction`；如果缺失，移动目标提示会不完整。
- 角色可以设置 `important: true` 标记为重要角色，但当前版本的 `npc_scheduler_agent` 仍有硬门槛：只有当 `char-player-0000` 到达该角色所在地图后，角色才会进入可调度候选。
- 普通场景制作时，建议仍只把承担教育目标、关键叙事职责或必要回应职责的角色设为 `important: true`；它可以服务叙事表达与后续扩展，但不会绕过“必须与玩家同图”这一激活条件。

### 3.5 state_change 原始输入
- `state_change_agent` 会接收 `source_input.raw_text`、`source_input.source_id`、`source_input.source_kind`。玩家分支传玩家原始输入，NPC 分支传 `npc_performer_agent` 输出的原始动作文本。
- 制作场景时不要依赖摘要替代原始动作；地图移动、拾取、交互等状态变化应能从原始输入或 NPC 原始动作文本中直接对应到世界实体。
### 3.5.1 state_change 物品位置
- 物品归属也通过 `item.location` 表达：在地上或场景容器中通常写地图 ID，在角色手上、身上、包内或被其保管时写角色 ID。
- “拿起/收到/接过/递给/交给/塞给”这类明确改变持有者的动作，应优先生成 `MOVE item.location = char-...`；“放下/放回/留在/置于某处”则应优先生成 `MOVE item.location = map-...`。
- `state_change_agent` 的 state view 会暴露当前地图上的物品，以及当前可见角色携带的物品；同时会在物品 `location` 的字段说明中列出当前地图、相邻地图和当前可见角色这些合法目标 ID。
- 如果场景设计希望玩家或 NPC 能继续转交、放下、归还某件物品，就不能只把该物品写进叙述文本，而应保证它始终以实体形式存在于 `store.items` 中。
### 3.6 NPC 对话记忆
- NPC 记忆包含 `dialogues` 与 `dialogue_log`。`dialogues` 是最近若干回合对话，会进入 `npc_performer_agent` 上下文；`dialogue_log` 只用于 debug 与回溯。
- 当 `npc_performer_agent` 输出 `intent="dialogue"` 时，系统会把玩家原始输入和 NPC 的 `action_text` 写入该 NPC 的 `dialogues`，超出窗口后压入 `dialogue_log`。
- 不要在世界配置里手写冗长历史对话；初始对话记忆应保持短小，只保留对角色行为判断必要的信息。

### 3.7 教育型场景设计建议
默认推荐把世界设计成“可互动的学习场景”，而不是单纯追求闯关与战斗刺激。

- 先写清楚场景的学习目标，例如人物关系理解、礼仪秩序辨识、文本线索分析、历史处境体会。
- 优先选择像《三顾茅庐》《林黛玉到贾府》这类具有明确文化信息密度的场景。
- 角色行为要符合身份、礼数、时代背景与原作气质。
- `recommended_inputs` / `scripted_inputs` 应覆盖观察、请教、比较、推理、表达态度等教育型互动，而不只覆盖攻击或战斗。
- 若场景允许冲突分支，也应把重点放在关系后果、礼法后果和情境理解上。
### 3.7.1 关系值与阶段结局
- 若场景重点在“是否被接纳”“是否得体融入”“是否赢得长辈信任”，优先使用 `CharacterEntity.status.*.value` 建模关系值，而不是临时写在叙述里。
- 数值变化应由 `state_change_agent` 在对应场景中按玩家原始输入与 `summary` 更新；注意 `UPDATE` 写的是变更后的新值，不是增量。
- 若需要“限定若干回合内达成某关系阈值，否则触发失败结局”，可再增加一个状态计数字段，由 `state_change_agent` 在该阶段每回合推进，并在 `end/endings.json` 中用 DSL 直接判断。
- 《林黛玉到贾府》的一个标准做法是：用 `char-jia_mu-0002.status.daiyu_favor` 表示贾母好感、用 `char-jia_baoyu-0003.status.daiyu_favor` 表示宝玉对黛玉初会的好感，并用各自的 `status.first_meet_rounds` 表示对应阶段已消耗回合；符合人设的有效互动每回合可加 10，失礼每回合减 5。当好感达到 55 时触发对应好结局，若阶段回合耗尽仍低于 55，则触发该阶段的失败次结局。
- 《三顾茅庐》可以复用同一模式：用 `char-zhuge_liang-0001.status.liubei_favor` 表示诸葛亮对刘备的认可，用 `char-zhuge_liang-0001.status.study_meet_rounds` 表示草庐书房会谈已消耗回合；符合刘备求贤若渴、持礼陈志的人设时每回合可加 10，失礼或催逼则减 5。当认可达到 55 时触发“请孔明出山”的好结局，若书房阶段回合耗尽仍低于 55，则触发“未能请出孔明”的次结局。
- 这类关系值字段不要只靠 prompt 自觉，必须在运行时加硬保护：仅允许玩家主分支在对应关键地图更新，NPC state 分支不得改；阶段计时每回合最多 `+1`，好感类字段每回合最多 `+10 / -5`。这样才能避免 NPC 旁支或异常补丁把阶段值提前推满。

## 4. 配置说明
主配置文件：`config/config.yaml`

关键配置：
- `llm`：模型、地址、key、温度、超时
- `system`：state patch 重试与降级
- `agent`：DM/NPC/Narrative 记忆窗口与预算
- `storage`：世界真值与叙事真值 SQLite 路径
- `description`：一致性维护触发阈值

优先级：命令行覆盖 > 环境变量 > 配置文件 > 默认值。

## 5. 运行方式
### 5.1 命令行 REPL
```powershell
python world/run_stage_main.py --mode phase3 --scene world/simple_stage_scene.json
```

### 5.2 Streamlit 游玩与调试
```powershell
streamlit run streamlit_app.py
```

在 UI 中你可以：
- 选择世界
- 切换 phase2/phase3/phase4
- 切换真实 LLM 与本地假服务
- 查看每回合 trace、快照、叙事池和 agent I/O

## 6. Agent 扩展工作流
当你修改任一 agent 时，建议固定顺序：
1. 更新 `docs/spec/draft_spec.md` 或对应 phase 要求
2. 更新 `src/data/model/*` 模型
3. 更新 `src/agent/prompt/*` 提示词
4. 更新 `src/agent/llm/*` 调用实现
5. 更新 `src/engine/engine.py` 的调用与集成
6. 补测试（`tests/phase*/`）并记录到 phase donelist

## 7. 调试与验收建议
### 7.1 trace_id 全链路追踪
使用 Streamlit Debug 面板，按回合查看：
- E1-E7 结构化链路
- 并发时间线
- 每个 agent 的输入/输出

### 7.2 双真值池检查
检查两个 SQLite：
- 世界真值：`world/world_snapshots.sqlite3`
- 叙事真值：`world/narrative_truth.sqlite3`

### 7.3 日志
- 结构化日志：`world/log/agent_io.jsonl`
- 全量测试日志：`world/log/full_test_*.log` / `full_test_*.json`

## 8. 常见问题
1. 启动时报敏捷属性缺失：
- 角色 attributes 中补齐 dexterity/敏捷。
2. 真实 LLM 调用失败：
- 检查 `api_key`、`api_base`、模型名和超时配置。
3. 回合触发状态回滚：
- 查看 Debug 面板中的 `state.error_history` 与 `fallback_error`。
4. 叙事与世界状态不一致：
- 关注一致性周期触发回合，查看 consistency 输出与阻断信息。

## 9. 交付建议
- 每次新增场景时，至少准备 10 条 scripted_inputs 做冒烟回放。
- 任何 agent 字段契约改动必须同步测试和文档。
- 每个新世界建议附带一份简短“学习目标”说明，明确玩家希望理解什么人物、礼仪或文化信息。
